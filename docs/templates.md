# 題組：內建的有哪些，怎麼自己寫一個

「題組」就是**今天要回答哪些問題**。程式裡沒有寫死任何一題——
每個題組都是一個 JSON 檔，放在 `data/templates/`，可以改、可以刪、可以複製給別人。

這份文件有兩部分：前半是**內建題組一覽**（可以當範例照抄），
後半是**怎麼自己寫一個**。

---

## 內建題組一覽

第一次啟動時，這 19 個題組會被複製到 `data/templates/`。
不喜歡的可以直接刪；刪掉之後不會自己跑回來。
想拿回某一個：`POST /api/templates/{id}/restore`。

> 內建這些題組都是往同一個方向問的：看清楚今天發生了什麼、對自己誠實、找出下一步。
> 寫自己的題組不必照辦，但這是它們長成這樣的原因。

### 與神同行

給每天靈修用的。這個工具最早就是為了這件事寫的。

| 題組 | 什麼時候用 |
|---|---|
| **快速打卡** `quick-checkin` | 很忙，但不想斷掉。全部用勾的，兩分鐘。 |
| **三段式（反省・靈修・代禱）** `three-part` | 手寫本最常見的分法，一段一個顏色。 |
| **同行日記（完整版）** `walk-with-jesus` | 想仔細自省的日子。逐項回答，最後留一段給神的話。 |
| **填空式靈修** `scripture-fill` | 不知道從哪寫起的時候。句子寫好了，只要填空。 |
| **星號隨筆** `free-bullets` | 不想被題目綁住，想到什麼寫什麼。 |
| **省察 · 一天的回看** `examen` | 睡前把一天在主面前重看一遍：謝恩、求光照、看見、認罪、交給明天。 |
| **哀歌 · 把痛苦帶到主面前** `lament` | 很難的日子。照詩篇哀歌的走法：呼求、訴說、求告、信靠、交託。 |

> 哀歌那一個是刻意留了位置給說不出口的話。詩篇裡有「我的神，我的神，為什麼離棄我」，
> 所以在主面前不用先整理好情緒才能開口。「就算什麼都還沒改變，我仍然相信的是」
> 那一題裡有一個選項是「我不確定，但我還在這裡」——那也是信心。

### 心情與難處

不預設信仰，任何人都可以用。難過、焦慮、心裡卡住的時候。

| 題組 | 什麼時候用 |
|---|---|
| **難熬的一天** `hard-day` | 今天很不好過。分開「事實」和「我自己加上去的解讀」，最後只找一件做得到的小事。 |
| **情緒盤點** `feelings` | 說不出來現在是什麼心情。從二十個詞裡挑，再找一個更準的。 |
| **擔心的事，分一分** `worry-sort` | 腦子停不下來。倒出來，分成「我能做的」和「做什麼都沒用的」。 |

### 成為什麼樣的人

寫日記真正的用處：有時間沉澱，看自己正在長成誰。

| 題組 | 什麼時候用 |
|---|---|
| **我想成為什麼樣的人** `become` | 先寫下想長成的樣子，再看今天哪一刻像、哪一刻不像。 |
| **高峰與低谷 · 得意時謙卑，難處中敬畏** `peaks-valleys` | 每天。今天最開心和最難受的各一件事，各問到底。上下各兩塊，可以練好幾次。 |
| **反思膠囊 · 今天的三件事** `capsule` | 每天。一件事想到底，經文和世上的智慧各問一次。一天一塊就夠。 |
| **月回顧 · 這個月我變成了誰** `month-review` | 一個月一次。不是檢討進度，是看有沒有往那個方向靠近。 |

這兩個是這裡面最花時間、也最有用的兩個練習：

**高峰與低谷** 的設計是：人的品格多半不是在平順的時候長出來的，是在得意和失意的時候
被決定的。所以高處不問「我多厲害」，問「這件事裡有多少不是我自己掙來的」和
「如果三個月後我因為這件事變得驕傲，會是從哪裡開始」；低處不停在痛上面，問
「哪些是我能決定的、哪些不是」（認出界線）、「信靠神在這件事上具體要做什麼」
（不是假裝沒事，是把不能決定的那一半交出去），最後問
「我可以怎麼讓身邊的人不必再踩一次同樣的坑」。
最後一段把高的和低的放在一起看，因為它們常常在講同一句話。

**反思膠囊** 一塊裡有六問：發生什麼、我的感受、學到什麼、
**哪一段經文用得上**、**哪個有智慧的人說過的話用得上**、我現在怎麼評價它。
經文那兩題是綠色 `#1f7a4d`，人的智慧那兩題是藍綠 `#2f7d86`——
輸出時看得出來哪句話從哪裡來。同樣的結構重複三塊，
一天只填一塊也完全成立（空白的段落輸出時不會出現）。

### 工作與創業

| 題組 | 什麼時候用 |
|---|---|
| **創業日記 · 每天** `founder-daily` | 今天推進了什麼、在驗證什麼假設、卡在哪裡，順便看一眼自己的體力。 |
| **決策紀錄** `decision-log` | 要做重要決定的那天。記下當時知道什麼、預期什麼，過一陣子回來對照。 |
| **週回顧** `week-review` | 週末十五分鐘：做完了什麼、時間花在哪、下週只做三件事。 |

> 決策紀錄有一段是「事後回來寫」，空著沒關係。重點是把「決定好不好」和
> 「結果好不好」分開——好決定也會碰上壞運氣。

### 簡單記一下

| 題組 | 什麼時候用 |
|---|---|
| **三行日記** `three-lines` | 一件事、一個感覺、一件謝謝。一分鐘，最不容易斷掉的那一種。 |
| **感恩清單** `gratitude` | 三件小事加一個人。寫久了會發現好東西一直都在。 |

## 一個題組長什麼樣

最短的一個，完整可用：

```json
{
  "id": "my-three",
  "name": "我的每日三問",
  "description": "睡前三分鐘。",
  "group": "簡單記一下",
  "order": 50,
  "sections": [
    {
      "id": "night",
      "title": "睡前",
      "color": "#2456b8",
      "icon": "☾",
      "fields": [
        { "id": "best", "label": "今天最好的一刻", "kind": "short_text" },
        { "id": "learn", "label": "學到什麼", "kind": "text" },
        {
          "id": "mood",
          "label": "今天整體",
          "kind": "scale",
          "options": [
            { "id": "good", "label": "好" },
            { "id": "ok", "label": "普通" },
            { "id": "bad", "label": "不好" }
          ]
        }
      ]
    }
  ]
}
```

存成 `data/templates/my-three.json`，重新整理頁面就會出現。

**沒寫的鍵就用預設值**，所以檔案可以很短。內建的題組也都是這樣寫的，
可以直接打開 `data/templates/` 裡任何一個來看。

## 題目的七種型態

`kind` 決定編輯器長什麼樣，也決定答案怎麼存。

| `kind` | 編輯器 | 存起來的樣子 |
|---|---|---|
| `text` | 大輸入框，可以換色 | HTML 字串 |
| `list` | 可增可減的編號行 | 字串陣列 |
| `short_text` | 一行 | 字串 |
| `choice` | 一排藥丸，點一下選起來 | 選中的 `option.id` |
| `multi_choice` | 同上，可複選 | `option.id` 陣列 |
| `scale` | 同上，有順序（滿意→缺乏） | 選中的 `option.id` |
| `fill` | 句子裡的 `{}` 變成行內填空 | 字串陣列，一格一個 |

`choice`／`multi_choice`／`scale` 需要 `options`；`fill` 需要 `pattern`。
其他型態不用。

`fill` 的 `pattern` 寫成一句話，用 `{}` 當空格：

```json
{
  "id": "sentence",
  "label": "一句話說清楚",
  "kind": "fill",
  "pattern": "我想成為一個 {} 的人，因為 {} 。"
}
```

輸出的時候，填進去的字會**變粗、上色**，沒填的地方會印成 `＿＿＿＿`。

## 每個鍵是什麼意思

### 題組

| 鍵 | 預設 | 說明 |
|---|---|---|
| `id` | 檔名 | 英數字、`-`、`_`。跟檔名一樣最省事。 |
| `name` | — | 側欄顯示的名字。 |
| `description` | `""` | 名字底下那一行小字。寫「什麼時候用它」最有用。 |
| `group` | `""` | 側欄的分類標題。同一群的排在一起；留白的會歸到最後的「其他」。 |
| `order` | `1000` | 排序，小的在前面。同數字就照檔名排。 |
| `default_theme` | `letterpress` | 紙張顏色：`letterpress`／`notebook`／`linen`／`dawn`／`midnight`。 |
| `default_layout` | `letter` | 輸出版型：`letter`／`ledger`／`manuscript`／`postcard`。 |
| `closing_label` | `給主的話` | 最後那個自由書寫欄叫什麼。 |
| `closing_hint` | 見預設 | 那一欄標題底下的說明。 |
| `closing_placeholder` | 見預設 | 那一欄空白時的提示字。 |
| `sections` | `[]` | 段落。 |

`closing_*` 三個鍵是給不談信仰的題組用的。`hard-day` 把它改成「寫給自己的話」，
`become` 改成「寫給未來的自己」，`decision-log` 改成「補充」。
改了以後，網頁輸出和圖片卡片上的標題都會跟著改。

### 段落

| 鍵 | 預設 | 說明 |
|---|---|---|
| `id` | — | 同一個題組裡不能重複。 |
| `title` | — | 段落標題。 |
| `color` | `#2f3437` | 這一段的主色。左邊的色條、標題、預設墨水色都跟著它。 |
| `icon` | `null` | 標題前的小圖示，一到兩個字元。 |
| `fields` | `[]` | 題目。 |

### 題目

| 鍵 | 預設 | 說明 |
|---|---|---|
| `id` | — | 同一個題組裡不能重複。**改了 id 等於換一題**，舊答案會變成「換題組後不顯示」的內容（不會被刪）。 |
| `label` | — | 題目本身。 |
| `kind` | `text` | 見上面七種。 |
| `options` | `[]` | 選項，`{"id","label"}`。 |
| `pattern` | `null` | `fill` 專用，用 `{}` 當空格。 |
| `placeholder` | `null` | 空白時的灰字提示。 |
| `min_rows` | `2` | `list` 一開始給幾行。 |
| `color` | `null` | 這一題答案的預設墨水色，不寫就跟著段落。 |
| `hint` | `null` | 接在題目後面的小提醒。**只在編輯器裡看得到，不會印到輸出上**——所以可以放引導的話。 |

## 寫題目的幾個心得

內建的題組都是照這幾條寫的，寫自己的時候可以參考：

**能用勾的就不要用寫的。** 最常見的失敗不是寫得不好，是那天沒有寫。
勾選題兩分鐘寫得完，寫得完才有下一天。

**一題只問一件事。** 「今天過得怎樣、有什麼想法？」沒人答得出來。
拆成「今天發生的一件事」和「我的感覺」就好答很多。

**把「事實」和「我的解讀」分開問。** 這是 `hard-day` 的整個重點。
同一件事，寫成事實和寫成解讀，讀起來會是兩件事。

**留一個誠實的選項。** `founder-daily` 問「卡住是因為」，選項裡有
「怕做錯」「其實不想做」；`decision-log` 問狀態，選項裡有「在裝有把握」。
這些選項沒人願意打字寫出來，但願意勾。

**問完感覺，要給一個出口。** 只把痛苦挖出來卻沒有下一步，寫完會更難受。
所以每個處理情緒的題組最後都有一段是「今天還做得到的一件小事」。

**空著也要能看。** 輸出時空白的題目會自動略過，所以題目可以多給一點，
使用者挑著答就好，不會因為沒填滿而覺得失敗。

**`hint` 是可以放溫柔的地方。** 它不會印到輸出上，所以適合寫
「再小都算」「看清楚就好，不用罵自己」「想不到就跳過」這種話。

**用顏色分開不同來源。** `capsule` 裡經文的欄位是綠色、人的智慧是藍綠色。
同一頁上兩種話都在，但一眼看得出來哪句從哪裡來。

**問完之後要有一個往外的題目。** `peaks-valleys` 高處問完「這件事讓我可以怎麼幫到別人」，
低處問完「我可以怎麼讓身邊的人不必再踩一次同樣的坑」。反思如果只停在自己身上，
寫久了會變成繞圈。

**加一題會讓人停一下的。** `decision-log` 問「這個決定會影響到誰？他們知道嗎？」
和「有沒有哪一部分是我不希望被人知道的？」；`founder-daily` 問
「今天有沒有為了推進，走了一條自己也覺得不太對的捷徑？」「今天誰因為我而過得辛苦？」。
趕的時候最容易略過的，通常就是最該問的那一題。

## 自己做一個

**最快**：側欄每個題組右邊有支鉛筆，點開就能改；「＋ 新增」從空白開一個。
編輯器裡可以設分類，也可以改結尾那一欄的名字。

**次快**：複製 `data/templates/` 裡最接近的一個，改檔名、改裡面的 `id`，
再改題目。改完重新整理頁面。

**注意**：`id` 一旦有日記在用就別再改了。改題組的 `id` 等於做了一個新題組，
舊日記會找不到它、退成純文字的「保留下來的內容」（內容仍然在，只是不好讀）。

## 分享出去

一個題組就是一個 JSON 檔，把檔案傳給別人、對方丟進 `data/templates/` 就能用。

整包搬家用「匯出全部」，會產生一個含日記、題組、版型與設定的 JSON。
匯入預設是**合併**——只會增加，不會蓋掉對方原本的東西。

如果做了覺得好用的題組，歡迎開 PR 放進 `app/seed/templates/`。
一個好題組能幫到的人，比一段程式碼多。
